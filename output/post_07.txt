  The comparator receives char** (not char*):

    int compare_strings(const void *a, const void *b) {
        const char *const *sa = (const char *const *)a;
        const char *const *sb = (const char *const *)b;
        return strcmp(*sa, *sb);  // dereference once
    }

  Why char** ? Because:
    Buffer: [ char* | char* | char* | char* ]
    qsort gives you a pointer TO each char* in the buffer.
    A pointer to a char* is a char**.

  For value types (int, Person), you get one level:
    Buffer: [ int  | int  | int  | int  ]
    qsort gives you int* for each element.

  Knowledge Test
═══════════════════════════════════════════════════════════

  Q: Write a comparator function that sorts Person structs
     by name. Why does qsort pass void** not void* when
     the array stores pointer types?

  A: The comparator for Person structs sorted by name:

     int compare_by_name(const void *a, const void *b) {
         const Person *pa = (const Person *)a;
         const Person *pb = (const Person *)b;
         return strcmp(pa->name, pb->name);
     }

     This works because Person is a value type — the array
     stores Person values directly in the buffer. qsort
     passes a pointer to each Person, so each argument
     is a Person* (cast to const void*).

     For pointer types (char*, Person*), qsort passes a
     pointer to the pointer. If the buffer holds char*
     values, each argument is a char** (cast to const
     void*). You must dereference once to get the char*.

     The rule: qsort always gives you &buffer[i], which
     is a pointer to whatever the buffer stores. For T,
     you get T*. For T*, you get T**.
