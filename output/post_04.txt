═══════════════════════════════════════════════════════════════
  Demo 5: Type mismatch — what goes wrong
═══════════════════════════════════════════════════════════════

  Created array with element_size = 4 (for int)
  Storing a double (3.14159, 8 bytes) — THIS IS A BUG!
  memcpy will copy only 4 of 8 bytes.

  Read back as int:    -266631570  (garbage — half the bytes of pi)
  Read back as double: 0.00000  (truncated — missing 4 bytes)

  Lesson: type erasure trades compile-time safety for flexibility.
  If you pass the wrong sizeof(), the compiler won't help you.
  Post 5 introduces macros that restore type safety.

  Knowledge Test
═══════════════════════════════════════════════════════════════

  Q: How do you access element i in a void* array with
     element_size = 20? Write the pointer arithmetic.

  A: void *elem = (char *)arr->data + i * 20;

     Cast data to char* (1-byte unit), then advance
     i * 20 bytes. The result is a void* pointing to
     the start of element i. Cast to the actual type
     to read the value:

       MyStruct *s = (MyStruct *)elem;
       printf("%d\n", s->field);

     Without element_size, you can't compute this offset.
     That single field is what makes generic arrays possible.
